## 设计决策（质疑阶段）

### Q1: Milvus 连接失败时是否降级到静态 scan

**决定**：不降级。快速失败 + 提示用户可用 `scan`/`analyze`，exit 1。理由：`ask` 和 `scan` 语义不对等（前者期待代码片段+LLM 解释，后者是文件统计），静默降级会掩盖问题。静态命令链路完全独立，Milvus 失败对其零感知。

### Q2: Insert 空输入是 no-op 还是 error

**决定**：no-op。`chunks == nil && vectors == nil` 返回 nil，不报错。与 Task 4 `RAGService.Index` 在无文档时 early return 自洽。非空 chunk 配空 vector 才视为错误。

### Q3: 旧 schema collection（缺新字段）如何处理

**决定**：检测到缺字段返回明确错误 `collection schema 过旧，缺少字段 %v，请删除后重新 index`，不自动 drop。避免误删用户数据。放 Task 7-8 由用户手动清理。

### Q4: `NewMilvusStore` 参数校验与网络连接顺序

**决定**：参数校验（address/collection 非空、vectorDim > 0）先于 `client.NewClient` dial。让"配置错"和"网络错"在错误信息上可区分。

### Schema 设计

collection 字段（`MilvusStore` 构造时由参数传入，不再硬编码 `code_segments`）：

```
id         Int64      主键, AutoID
chunk_id   VarChar(512)
source     VarChar(512)
content    VarChar(10000)
start_line Int32
end_line   Int32
chunk_type VarChar(64)
vector     FloatVector(dim 由参数传入)
```

索引：HNSW（COSINE, M=16, efConstruction=64），与旧 `InitCode` 保持一致。

### P1 修复

`milvus_store.go:287` `mapMilvusResults` 签名变更：

```go
// 修复前
func mapMilvusResults(raw []client.SearchResult) []SearchResult

// 修复后
func mapMilvusResults(raw []client.SearchResult) ([]SearchResult, error)
```

遍历开头检查 `r.Err != nil` → 返回 `fmt.Errorf("milvus: 第 %d 路 search result 解析失败: %w", i, r.Err)`。

连带修改：
- `Search` 方法末尾改为 `return mapMilvusResults(rawResults)` 透传 error
- 内层循环变量 `i` 重命名为 `j` 避免遮蔽外层 `range` 的 `i`
- 测试文件两处调用点同步改为 `results, err := mapMilvusResults(raw)`
- 补 `TestMapMilvusResults_PropagatesResultErr`：构造 `SearchResult{Err: ...}`，断言返回 error 且 wrap 原始消息
