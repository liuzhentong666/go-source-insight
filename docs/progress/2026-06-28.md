### w9 bug 命令错误传播修复

**问题发现**

`bug` 命令在使用非 Go 文件 / 非法 Go 代码输入时返回 exit 0，与其他命令（security / complexity / test）行为不一致。根因：

- `BugDetector.Run()` 在解析失败时将错误吞入 `errorFiles` 列表并 `continue`，始终返回 `err == nil`
- `ToolManager.Run()` 因 `err == nil` 设置 `Success=true`
- `bug` 命令缺少 `!result.Success` 检查

**修复内容**

| 文件 | 修改 |
|------|------|
| `internal/tools/bug_detector.go` | 全部 Go 文件解析失败时返回 error（比照）：`len(errorFiles) == len(goFiles)` → 返回 error；部分失败保留 partial JSON |
| `internal/cli/commands/bug.go` | 补 `!bugResult.Success` 检查，与 security / complexity / test 对齐 |
| `internal/tools/bug_detector_test.go` | `TestBugDetector_EmptyCode` / `TestBugDetector_SyntaxError` 更新为期望 error |

**跨层影响验证**

| 路径 | 行为 | 影响 |
|------|------|------|
| `bug` 命令 + 非 Go / 非法代码 | exit 1（新行为） | ✅ 符合预期 |
| `analyze` + 正常 Go | 不变 | 0 |
| `analyze` + 混合目录 | 非 Go 被 scan 跳过 | 0 |
| `analyze` + 语法错误 Go | complexity_analyzer 先拦截，bug_detector 未执行 | 0 |

- `file_analyzer.go` / `tool_manager.go` / `cmd/main.go` 不需要修改

**CLI 集成测试**
