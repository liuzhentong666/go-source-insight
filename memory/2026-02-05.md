### 核心技术

#### 1. 圈复杂度计算
**公式：** 圈复杂度 = 1 (基础路径) + 判定点数量

**支持的判定点：**
- `if` 语句
- `for` 循环
- `range` 循环
- `switch` 语句
- `case` 分支
- `select` 语句
- `&&` 和 `||` 逻辑运算符

#### 2. 复杂度分级
| 复杂度范围 | 等级 | 处理建议 |
|-----------|------|---------|
| 1-10 | Simple | ✅ 正常 |
| 11-20 | Medium | ⚠️ 可关注 |
| 21-50 | Complex | ❌ 建议拆分 |
| >50 | VeryComplex | 🚨 必须拆分 |

#### 3. AST 遍历
使用 `ast.Inspect()` 遍历语法树，提取所有 `*ast.FuncDecl` 节点。

#### 4. 数据结构
```go
type FunctionResult struct {
    Name       string   `json:"name"`
    Line       int      `json:"line"`
    Complexity int      `json:"complexity"`
    Lines      int      `json:"lines"`
    Issues     []string `json:"issues"`
}

type ComplexityResult struct {
    File       string           `json:"file"`
    Total      int              `json:"total"`
    Functions  []FunctionResult `json:"functions"`
    Summary    string           `json:"summary"`
    Statistics Statistics       `json:"statistics"`
}
```

### 核心设计

#### 1. 规则驱动架构
```go
type SecurityRule interface {
    ID() string
    Name() string
    Category() string
    Severity() string
    Description() string
    Suggestion() string
    Match(node ast.Node, ctx *RuleContext) bool
}
```

#### 2. 检测规则（7 个）
| 规则 ID | 名称 | 类别 | 严重程度 | 检测内容 |
|---------|------|------|---------|---------|
| G101 | Hardcoded Secrets | Credentials | Critical | 硬编码密码/密钥 |
| G201 | SQL Injection | Injection | Critical | SQL 注入风险 |
| G401 | Weak Random | Cryptography | High | 不安全随机数（math/rand） |
| G104 | Info Disclosure | Data Privacy | Medium | 敏感信息打印 |
| G501 | Weak Encryption | Cryptography | High | 弱加密算法（MD5、SHA1） |
| G302 | Insecure File Perm | File System | Medium | 不安全文件权限（0777） |
| G107 | Insecure HTTP | Network Security | Medium | HTTP 而非 HTTPS |

#### 3. 检测技术
**AST 模式匹配：**
- `*ast.AssignStmt` - 检测硬编码密钥
- `*ast.BinaryExpr` - 检测 SQL 注入（字符串拼接）
- `*ast.SelectorExpr` - 检测不安全函数调用（math/rand、md5）
- `*ast.CallExpr` - 检测敏感信息打印、文件操作、HTTP 请求

**关键词检测：**
```go
var secretKeywords = []string{
    "password", "passwd", "secret", "api_key",
    "access_token", "private_key", "credential",
}
```

#### 4. 纯检测工具设计
**为什么不做自动修复？**
- 安全问题需要上下文理解
- 自动修复可能引入新 Bug
- 需要人工审查和测试

**处理流程：**
```
SecurityScanner 检测 → 生成报告 → AI 解读 → 开发者修复
```

#### 5. 去重机制
避免同一位置被多个规则匹配：
```go
key := fmt.Sprintf("%s-%d", issue.RuleID, issue.Line)
```

## 学习要点

### 1. AST 结构理解
- Go 代码解析为抽象语法树（AST）
- 每个语法结构对应一个 ast.Node 类型
- 使用 `ast.Inspect()` 遍历整个语法树

### 2. 模式匹配技巧
- 类型断言：`if fn, ok := n.(*ast.FuncDecl); ok`
- 递归遍历查找父节点
- 结合 `token.FileSet` 获取行列号

### 3. 规则引擎设计
- 接口抽象：`SecurityRule` 接口
- 可扩展性：添加新规则只需实现接口
- 独立测试：每个规则可单独测试

### 4. 错误处理
- 解析错误：`parser.ParseFile()` 返回错误
- 输入验证：检查空字符串、类型错误
- 错误信息：提供清晰的错误描述
